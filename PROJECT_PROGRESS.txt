OCSR Project Progress Log
=========================

Project:
Optical Chemical Structure Recognition (OCSR): Comparative Evaluation of Deep
Learning Approaches for Molecular Structure Extraction


Current Scope
-------------

The project has been narrowed from implementing three full OCSR architectures
from scratch to building a working baseline and then improving toward a more
correct OCSR formulation.

Current active baseline:

- CNN-GRU image-to-SMILES sequence baseline
- Input: rendered molecule image
- Output: generated SMILES token sequence
- Purpose: simplified image-to-sequence OCSR model inspired by SwinOCSR

Historical classifier experiment:

- A CNN closed-set classification baseline was implemented and tested first.
- That path has now been removed from the active codebase.
- The result is kept in this progress log for the report because it explains
  why the project moved to image-to-sequence modeling.

Historical classifier limitation:

- The CNN classifier is not full OCSR sequence generation.
- It treats each unique SMILES string as a separate class.
- It cannot generate a novel SMILES string for a molecule outside the
  learned class labels.

  dataset such as EPA without retraining.

Observed trends:

- Higher learning rate performed better in this grid.
- Average test token accuracy by learning rate:
  - 0.001: 0.6367
  - 0.0005: 0.5883
  - 0.0001: 0.4849
- Larger GRU hidden dimension improved token accuracy.
- Average test token accuracy by hidden dimension:
  - 128: 0.5260
  - 256: 0.5741
  - 512: 0.6098
- Average train/test token-accuracy gap by hidden dimension:
  - 128: 0.0058
  - 256: 0.0110
  - 512: 0.0215
- Exact match and canonical match remained 0.0 for every run.
- This means the model learned useful local SMILES token patterns, but did not
  generate fully correct molecular strings.
- Larger hidden dimension shows slightly more overfitting, but test accuracy
  also improves, so hidden_dim 512 remains the strongest setting so far.
- The main issue is not severe overfitting. The larger issue is full-sequence
  correctness: generating a valid/correct molecule is much harder than
  predicting many individual tokens correctly.
- Valid SMILES rate should be interpreted carefully: a generated SMILES can be
  syntactically valid while still representing the wrong molecule.

Report-ready interpretation:

"Increasing the GRU hidden dimension and learning rate improved token-level
accuracy, with the best result from learning rate 0.001 and hidden dimension
512. However, exact and canonical match remained zero, indicating that the model
learned local sequence patterns but not complete chemically correct SMILES
generation."

Interpretation of CNN Results
-----------------------------

The CNN pipeline is working, but the learning task is poorly matched to the
dataset.

Reason:

- The model is a closed-set classifier.
- Each molecule appears only once.
- The train/test split puts different individual molecules into train and test.
- Therefore the test set contains molecule classes that the CNN has not learned
  from repeated examples.

This explains why the model predicts the same SMILES repeatedly and obtains
zero test accuracy.

Report language to use:

"The CNN baseline was implemented as a closed-set image classifier where each
unique SMILES string is treated as a class. Because the PubChem subset contains
one image per molecule, the model receives only one example per class. This
causes a mismatch between the classification formulation and the OCSR task,
where the desired behavior is to generate a molecular representation for new
chemical structures."


Paper Understanding
-------------------

The primary reference paper is:

Xu et al., "SwinOCSR: End-to-end optical chemical structure recognition using a
Swin Transformer," Journal of Cheminformatics, 2022.

Key understanding:

- SwinOCSR does not classify each molecule as a separate class.
- It treats OCSR as image-to-sequence translation.
- Input: chemical structure image
- Output: DeepSMILES token sequence

SwinOCSR architecture:

- Swin Transformer image backbone
- Transformer encoder
- Transformer decoder
- DeepSMILES token output

Training details from the paper:

- Image size: 224 x 224
- Dataset size: about 5 million generated molecule images
- Split ratio: 18:1:1
- Train size: about 4.5 million
- Validation size: about 250,000
- Test size: about 250,000
- Batch size: 256
- Optimizer: Adam
- Learning rate: 5e-4
- Training: 30 epochs
- Hardware: NVIDIA Tesla V100 GPUs

Important conclusion:

The paper can train/test on unique molecules because the model learns reusable
visual-to-token patterns rather than memorizing molecule class IDs.


Current Technical Limitation
----------------------------

The historical CNN classifier is useful as a report baseline, but it is not a
correct full OCSR model.

The CNN-GRU sequence model is closer to the correct OCSR formulation, but the
current dataset contains relatively complex molecules for a first sequence
generation experiment.

Current sequence-model limitation:

- It learns partial token patterns.
- It does not yet reliably predict END tokens.
- It produces invalid SMILES with repeated fragments and unmatched parentheses.

Recent implementation improvements:

- Training can now be configured from the command line with dataset name,
  learning rate, hidden size, embedding size, epochs, and batch size.
- Evaluation now includes valid SMILES rate in addition to token accuracy,
  exact match, and canonical match.
- Greedy decoding now stops early when all samples predict the END token.
- RDKit parse-warning spam is suppressed during canonical evaluation.
- The optional PubChem-simple filtering script was removed so the active project
  has one main dataset workflow.
- A hyperparameter-grid script was added for the course tuning requirement.
- Sequence metrics were changed to append all runs into one shared CSV instead
  of creating a separate CSV file for every hyperparameter setting.
- LSTM and attention-based decoders were considered but moved to future work so
  the active implementation stays focused on the CNN-GRU model.
- PROJECT_REFERENCE.md was added to document files, functions, and commands.

Implemented architecture:

image -> CNN encoder -> GRU decoder -> SMILES token sequence

This model uses teacher forcing during training and greedy decoding during
evaluation.


Dataset Direction
-----------------

Decision:

- Continue using PubChem as the main data source because it is realistic,
  reproducible, and provides SMILES labels.
- Do not switch to a hand-made toy dataset as the main experiment.
- Keep one main PubChem dataset path in the active codebase to reduce file
  sprawl.
- A filtered PubChem-simple subset was considered as a possible debugging step,
  but the helper script was removed from the active project.

Report framing:

"PubChem was used because it provides reproducible molecular structures and
corresponding SMILES labels. A simpler filtered subset was considered during
development, but the active implementation was kept focused on one reproducible
PubChem workflow."

Report Framing Notes
--------------------

Useful framing:

- The project began with an ambitious comparison of CNN-based,
  Transformer-based, and graph-based OCSR methods.
- Professor feedback identified feasibility risk in implementing all three
  advanced architectures from scratch.
- The implementation was narrowed first to a working CNN baseline.
- Running the CNN revealed an important methodological issue: OCSR should not
  generally be formulated as simple molecule classification when the goal is to
  recognize unseen structures.
- This motivated the implemented image-to-sequence CNN-GRU model, which better
  matches the SwinOCSR paper.
- The sequence model achieved nonzero token accuracy but generated invalid full
  SMILES, motivating future improvements to decoding, model capacity, or
  dataset preprocessing.
